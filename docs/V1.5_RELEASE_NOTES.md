# V1.5

V1.5 adds an optional native-LAN MQTT broker workflow without changing the
existing MQTT client API.

## New broker components

- `addons/mqtt/simulated_broker.tscn` provides the deliberately limited MQTT
  3.1.1 broker used by local development and tests.
- `addons/mqtt/lan_broker.tscn` discovers an existing broker or elects one
  application instance to host it. Multiple applications can use identical
  startup logic and converge on one endpoint.
- Broker-to-subscriber `PUBLISH` delivery can inject seeded latency, jitter,
  loss, duplication, bounded reordering, hold-and-burst behaviour and connection
  interruption. MQTT control packets remain reliable.
- The MQTT client, simulated broker and LAN broker are quiet by default;
  applications opt into console diagnostics explicitly.

The broker is intended for trusted native LAN development and smoke tests. It
is not a replacement for a managed broker and does not provide authentication,
TLS, persistence, WebSockets, QoS 2 or automatic host failover.

## Compatibility

The existing `mqtt.gd` client API remains the V1.4-compatible API. Projects
that only vendor `mqtt.gd`, `mqtt.tscn` and their existing resources do not need
to adopt the broker components.

See `SIMULATED_BROKER_SCOPE.md` for the supported MQTT subset and fault-profile
fields. See `TWOVOIP_VENDORING.md` for the downstream integration recipe.
